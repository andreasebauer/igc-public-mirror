The V1.5 run is computationally sound and reproducible. It really does find recurrent classes of exact connected-node carriers that share the same V1.3 current-action support and the same action-labelled one-step successor profile under the frozen V1.5 definition.

However, the audit found the next distinction that matters: V1.5 performs only ONE partition-refinement step. Its successors are colored by the coarser V1.3 C0 class, not by V1.5 C1 itself. When the audit asks the next recursive question — do exact members of one C1 class also have the same action-labelled transitions to C1 classes? — some C1 classes split. Therefore C1 is not yet a fixed-point behavioral quotient and cannot yet support a claim of arbitrary future substitutability.

This is not a failure of the algebra. It is exactly the kind of hidden distinction the observer program is supposed to expose.

2. WHAT V1.5 REALLY ESTABLISHES
===============================

V1.5 defines:

C0 = V1.3 current-action support class.

For each exact carrier x it then enumerates every legal one-relation child, exact-deduplicates those children, labels the action by the anonymous typed port-pair class, and records:
- R: the set of (action label, C0(child)) outcomes;
- M: the number of exact child classes in each (action label, C0(child)) outcome.

Then:

C1(x) = hash(C0(x), R(x), M(x)).

This is a genuine strengthening of V1.3. At k128:
- exact selected carriers: 941
- V1.5 C1 classes: 275
- exact→C1 compression: 3.421818×
- C1 classes with >=2 exact realizations: 39
- largest C1 class: 257 exact realizations

So many different exact connection networks really do collapse to the same one-step transition-refined type.

The raw recurrence count is 5,815 C1 classes, but that number should not be overinterpreted:
- median longest contiguous span: 3 k-levels
- mean longest contiguous span: 5.7422 k-levels
- span >=48: 52 classes
- span all k0→k128: 10 classes

Among the 5,815 recurrent classes:
- 2,624 have >=2 exact realizations at least once;
- 1,133 have >=2 exact realizations on adjacent k checkpoints.

Thus the substantive retrospective existence claim survives, even though the headline count is dominated by short recurrences.


3. CRITICAL SCIENTIFIC FINDING: C1 IS NOT A FIXED POINT
=======================================================

The V1.3 audit taught us that “same capabilities now” did not guarantee “same tomorrow.” V1.5 addressed that by comparing one-step successors, but it colors those successors with C0.

The natural next audit is therefore:

C2 = current C1 + action-labelled successor profiles where successors are colored by C1.

If a C1 class is already a stable transition congruence, all exact realizations inside it must remain together under this second refinement.

They do not.

5. SPEC / IMPLEMENTATION AUDIT ISSUES
=====================================

5.1 HIGH — source-integrity fail-closed contract is incomplete
-------------------------------------------------------------
Frozen Section 2 says the implementation MUST verify:
- V1.2 science SHA;
- V1.3 science SHA;
- V1.3 freeze SHA;
- complete k0→k128 panels/required files;
and fail closed on mismatch.

The V1.5 source_integrity() implementation verifies V1.2 and V1.3 science hashes and checks that required files exist, but it does NOT verify the V1.3 freeze SHA and does NOT hash the parent selected-carrier panels.

This is a real guardrail defect because the V1.2 final science hash does not itself commit to every selected-carrier file; it is a summary hash.

For this actual run, the audit independently verified the existing V1.3 parent-trajectory manifest against the source data and found 130/130 exact matches, and the V1.3 freeze SHA is correct. Therefore this issue does not invalidate the current result. It must be repaired before the prospective continuation.

5.2 MEDIUM — retrospective status logic is weaker than frozen Section 14
-----------------------------------------------------------------------
Section 14 says immediate retrospective success requires, among other things, C1 classes with >=2 exact realizations and recurrence across k.

retrospective_summary() currently calls any C1 class recurring for two consecutive k-levels a recurrent entity and sets RETROSPECTIVE_TRANSITION_REFINED_ENTITY_FOUND_V1_5 if at least one such recurrence exists, even if it is always a singleton.

The current science conclusion survives this bug because the actual data contain 2,624 recurrent classes with multiple realizations at least once and 1,133 with multiple realizations on adjacent k-levels. But the evaluator should be corrected to match the frozen wording exactly.

5.4 LOW — synthetic tests are too narrow

The frozen synthetic test checks:

It does not test:

PLAIN-LANGUAGE SUMMARY
======================

V1.5 was a real improvement, and the run is good.

It found many different connection networks that look the same now and also have the same kinds of immediate next moves. That is real compression.

But the audit looked one move further. For some networks that V1.5 calls the same thing, their next states do not themselves have the same future possibilities. So we have not yet found the final definition of the higher-order object.

The nice part is that we do not have to invent what is missing. We can repeat the same sorting rule automatically: whenever two supposedly identical objects behave differently later, split them. Keep doing that until nothing splits anymore.

If that process eventually stops with a small reusable set of classes, the algebra itself will have told us what information a genuine connected higher-order node must carry.

That is the next clean experiment.
